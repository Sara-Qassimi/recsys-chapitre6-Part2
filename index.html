    Recommender Systems · Chapter 6 · Part 2

    Deep learning for recommendation: residual networks and autoencoders

    Part 1 built matrix factorization, a linear model. This part adds neural networks in two ways: a network that corrects MF, and an autoencoder that rebuilds a user's whole rating vector. Then we compute the error with missing ratings and train on a matrix too big for memory.

    Problem

    Matrix factorization is linear

    Matrix factorization adds up products of numbers, so it can only express simple, linear tastes. Some ratings depend on combinations that a dot product cannot capture. Neural networks can learn such non-linear patterns; the question is how to add them without losing what MF does well.

    Matrix factorization (Part 1)

    r̂ = wᵀu + b + c + μfast, compact, accurate, but LINEAR: sums of products. Misses interactions, thresholds, non-linear tastes. On our table (K = 1): errors up to 0.93 star.

    Neural networks (this part)

    learn non-linear patterns. Two ways: 1. Residual network: MF + a network that corrects MF. 2. Autoencoder: a network that rebuilds a user's whole rating vector.
    Problem statement

    The questions this part answers

    Five questions, one per part. Q1 is about improving MF with a network, Q2 and Q3 about autoencoders and how they fill missing ratings, Q4 about computing the error correctly, and Q5 about training on a matrix that does not fit in memory.

    01

    Residual networks

    r̂ = MF + ANN: a neural network learns what matrix factorization misses.

    Inspiration

    ResNet and Inception, borrowed for recommendation

    In image recognition, ResNet adds shortcut connections so that a block only learns a correction to its input, and Inception runs several branches in parallel and combines them. We borrow both ideas: keep a simple model (MF, linear), add a branch that learns a correction (a neural network, non-linear), and combine the outputs.
    Formula

    Residual network: r̂ = MF(x) + ANN(x)

    The part of the rating that MF gets wrong is the residual: actual − predicted. The final prediction is the MF prediction plus the network's output, joined by an Add() layer, so the network ends up learning the error of MF. Careful: in the tutorial both branches are trained together, end to end, on the final error, not one after the other.
    x = (user, movie) · MF(x) = wᵀu (+ biases) · ANN(x) = the correctionr̂ = MF(x) + ANN(x)    residual = r − MF(x)
    Example: MF predicts 4, the actual rating is 5. The network adds +0.7, so the final prediction is 4.7: the error drops from 1 to 0.3. If the network learned nothing and output 0, the model would simply be MF.

    Compute residuals and corrections

    For each case, subtract the MF prediction from the actual rating to get the residual. Then add the network's output to the MF prediction. Compare the two errors to see whether the correction helped. Edit the table to test other cases.

    A: residual 3 − 3.8 = −0.8, final 3.3, |error| 0.8 → 0.3 ✓ · B: residual +1.5, final 2.5 + 0.9 = 3.4, 1.5 → 0.6 ✓ · C: residual −0.2, final 4.5, 0.2 → 0.5 ✗. In case C the ANN pushed in the wrong direction. On new data this is the sign of an overfitted correction branch: regularize it (dropout, L2) and check the TEST MSE. A good correction has the same sign as the residual and a smaller size.

    Tutorial

    Residual network in Keras: one Add() layer

    You already built MF in Keras (Embedding + Dot) and a neural network (Embedding + Dense). To make the residual network, add one layer that sums their two outputs, and train with one loss. On 17 ratings a network would simply memorize the residuals: this needs real data (MovieLens).
    u = Input(shape=(1,));  m = Input(shape=(1,))
u_emb = Embedding(N, K)(u);  m_emb = Embedding(M, K)(m)

# branch 1: matrix factorization (linear)
mf = Dot(axes=2)([u_emb, m_emb])
mf = Add()([mf, Embedding(N, 1)(u), Embedding(M, 1)(m)])   # + biases
mf = Flatten()(mf)

# branch 2: neural network (non-linear correction)
ann = Flatten()(Concatenate()([u_emb, m_emb]))
ann = Dense(400, activation="relu")(ann)
ann = Dropout(0.5)(ann)
ann = Dense(1)(ann)

out = Add()([mf, ann])                    # r̂ = MF(x) + ANN(x)
model = Model([u, m], out)
model.compile(loss="mse", optimizer=SGD(learning_rate=0.08, momentum=0.9))
model.fit([users, movies], ratings - mu, validation_data=..., epochs=...)

    02

    Autoencoders

    A network that reproduces its own input through a small code.

    Explanation

    A network that reproduces its own input

    An autoencoder is trained to output its own input. The hidden layer is smaller than the input, so the network cannot simply copy: it must learn a compact summary. The only change in code is that the target is X instead of y: model.fit(X, X). AutoRec (WWW 2015) is the paper that introduced autoencoders for collaborative filtering; its best variant uses item columns, the course uses user rows, which is easier to follow.
    Explanation

    Encoder, code, decoder

    The encoder compresses the input into a few numbers, the code. The decoder turns the code back into a full vector. For ratings, the code summarizes the user's taste, like the user vector wi of MF, and the decoder plays the role of U: it produces a rating for every movie, including the missing ones.
    Movie 1Movie 2Movie 3Movie 4Movie 5
    Input x530 (missing)40 (missing)
    Output x̂534.543.2
    Rebuilt known ratings = training signal. Rebuilt missing ratings = predictions (4.5 and 3.2). The error is computed only where an actual rating exists (positions 1, 2, 4): Part 4 builds this with a mask.
    Exercise 2

    Count the weights of an AutoRec

    Each dense layer has one weight per connection plus one bias per output unit. Count the two layers separately and add them. Then think about where the users appear: as parameters, or as data passed through the network?
    Try it · AutoRec vs MF, number of parameters

    26,000 × 700 + 700 = 18,200,700 · 700 × 26,000 + 26,000 = 18,226,000 · total 36,426,700 ≈ 36.4 M, about 23 × MF with K = 10 (1.56 M). The users are not parameters: they are the samples passed through the network. The same weights serve every user, even a new one who has a few ratings.

    03

    Denoising & AutoRec

    Corrupt the input on purpose, so the network learns to fill the gaps.

    Explanation

    From missing pixels to missing ratings

    A denoising autoencoder receives a damaged input, for example an image with some pixels set to zero, and must rebuild the clean version: it learns to complete missing parts, exactly the problem of missing ratings. Images and ratings have the same table shape (row = image or user, column = pixel or movie). What changes is what one sample is: one rating for the residual network, one whole user row for AutoRec.
    Correction

    Why is AutoRec faster? Fewer, bigger samples

    Careful: the original slide inverts the reason. AutoRec is faster per epoch because it loops over 130,000 user rows, not over 20 million individual ratings. Each row (26,000 values) is processed as one efficient matrix operation.
    Try it · samples and batches per epoch

    Residual network: 20,000,000 samples (one per rating), 20 M / 128 = 156,250 batches, 3 values per sample (user, movie, rating) · AutoRec: 130,000 samples (one per user), 20 M / 130 k ≈ 154 × fewer, ⌈130,000 / 128⌉ = 1,016 batches, 26,000 values per sample. Fewer, larger samples suit matrix operations on CPU and GPU.

    Explanation

    Dropout and noise on the input

    During training we hide some known ratings by setting them to 0, while the target stays the original vector. The network must still output the hidden ratings, so it learns to predict missing values instead of copying its input. This also reduces overfitting. Common rates: 0.2 to 0.5, only during training, never at prediction time.

    04

    Masked loss and test MSE

    Only known ratings count; never let the model copy the test ratings.

    Formula

    The cost must ignore the missing ratings

    An autoencoder tries to reproduce its input, zeros included. If the loss counted the zeros, the network would learn that missing ratings are 0 stars. The mask is 1 for known ratings and 0 for missing ones, so only known ratings count. Divide by the number of KNOWN ratings, not by the vector length.
    J = Σi Σj mij (rij − r̂ij)² / Σi Σj mij    mij = 1 if rij is known, else 0
    def masked_mse(y_true, y_pred):
    mask = K.cast(K.not_equal(y_true, 0), "float32")   # 1 = known rating
    sq = (y_pred - y_true) ** 2 * mask
    return K.sum(sq) / K.sum(mask)                      # divide by #known
    Exercise 4

    Masked vs unmasked error

    Compute the error twice: once only on the known ratings, once on all positions with target 0 for the missing ones. Compare the two values and see which positions dominate the unmasked error. Input: [5, 0, 3, 0, 4] · output: [4.6, 4.5, 3.4, 3.2, 4.2].
    Try it · the mask, step by step

    Mask [1, 0, 1, 0, 1] · squared errors 0.16, 20.25, 0.16, 10.24, 0.04 · masked (0.16 + 0.16 + 0.04) / 3 = 0.12 · unmasked 30.85 / 5 = 6.17. Unmasked, 98.8% of the loss comes from the two missing cells, so training would push those outputs toward 0: "missing = 0 star". Always mask.

    Explanation

    Test MSE: never feed the test ratings as input

    If the test ratings were part of the input, the autoencoder could simply copy them and get a perfect but meaningless test score. So the input is built from the training ratings only, and the test ratings are used only as targets, with a test mask. In code: pred = model.predict(X_train), then compare with X_test.

    Exercise 5

    Compute a test MSE

    Build the test mask from the test row and compare the output with the test ratings at those positions. Then do the same with the train row and its mask. The output is the same for both computations. Train row [5, 0, 3, 0, 0] · test row [0, 3, 0, 0, 4] · output from train [4.8, 3.5, 3.1, 2.9, 3.6].

    Test mask [0, 1, 0, 0, 1] · (3 − 3.5)² + (4 − 3.6)² = 0.25 + 0.16 → 0.205 · train mask [1, 0, 1, 0, 0] · 0.04 + 0.01 → 0.025. Test ≈ 8 × train: expected, the model never saw the test ratings. Only the test MSE measures prediction quality.

    05

    Lab: sparse data

    Feed a huge sparse matrix to Keras in batches.

    Explanation

    Sparse matrices: store only the ratings

    The full rating matrix is far too big for memory, but the autoencoder needs its rows. SciPy sparse formats store only the actual ratings: lil_matrix is easy to fill, csr_matrix gives fast row slicing, coo_matrix stores (row, col, value) triples. Keras needs dense arrays, so we convert small batches one at a time. Store sparse, train dense.
    Try it · dense vs sparse memory
    Exercise 6

    Dense vs sparse memory

    1 million users × 10,000 items, 5 million ratings. For the dense matrix, multiply the number of cells by 4 bytes (float32). For CSR, count 8 bytes per rating (value + column index) plus 4 bytes per row pointer (N + 1). Then compute one dense batch of 128 users.

    10⁶ × 10⁴ × 4 B = 40 GB · 5 × 10⁶ × 8 B + (10⁶ + 1) × 4 B ≈ 44 MB · 128 × 10,000 × 4 B = 5.12 MB · 40 GB / 44 MB ≈ 900 × smaller. During training only one dense batch is in memory at a time.

    Explanation

    Batch processing: batches of users

    We process the matrix in batches of users. Careful: the original example also splits the items ("10,000 users by 1,000 items"). That breaks the network, whose input layer has exactly M units. A batch must contain some users and ALL the items: shape (batch_size, M).
    Your turn · valid batch or not?
    def generator(A, M, bs=128, p=0.5):          # A: ratings (CSR), M: mask (CSR)
    while True:
        A, M = shuffle(A, M)
        for i in range(0, A.shape[0], bs):
            a = A[i:i+bs].toarray()            # some users, ALL items
            m = M[i:i+bs].toarray()
            noisy = a * (np.random.random(a.shape) > p)   # input noise
            yield noisy, a                     # input, target

model.fit(generator(A, M), steps_per_epoch=A.shape[0] // 128, epochs=...)

    Limits

    What deep models add, and what they cost

    Deep models capture non-linear patterns and share their weights across all users. But they have many more parameters (36 M vs 1.6 M for MF), many settings to tune (hidden size, dropout, learning rate), a real risk of overfitting, and they still cannot help a user with no rating. Rule of thumb: start from MF; add a deep model only if the TEST MSE really improves.
